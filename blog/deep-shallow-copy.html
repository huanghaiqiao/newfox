深浅拷贝

1. 概念：什么是浅拷贝 / 深拷贝？

当一个对象里包含 指针/动态资源（例如 new 出来的内存、文件句柄、socket、互斥锁等）时，拷贝对象会面临“资源所有权”问题：

  • 浅拷贝（Shallow Copy）：只把成员变量的值逐位复制。若成员是指针，复制后两个对象的指针会指向 同一块堆内存。
  • 深拷贝（Deep Copy）：不仅复制成员变量值，还会为“资源型成员” 重新申请一份独立资源，并复制资源内容。这样两个对象互不影响，各自释放各自的资源。

一句话：浅拷贝复制“指针值”，深拷贝复制“指针指向的内容”。

2. 为什么浅拷贝危险？

以“堆内存指针”为例，浅拷贝常见问题：

  1. 重复释放（double free）：两个对象析构时都会 delete 同一块内存 → 未定义行为（可能崩溃）。
  2. 修改互相影响：一个对象通过指针修改数据，会影响另一个对象看到的数据。

3. C++ 中何时会发生拷贝？

常见触发拷贝构造/拷贝赋值的场景：

  • MyClass b = a;（拷贝构造）
  • MyClass b(a);（拷贝构造）
  • 函数参数 按值传递：void f(MyClass x);
  • 函数 按值返回（可能触发拷贝/移动，取决于优化与版本）
  • b = a;（拷贝赋值）

4. 示例：为指针成员实现深拷贝（Rule of 3/5）

下面这个类拥有堆内存 data，因此需要自定义：

  • 拷贝构造函数（deep copy）
  • 拷贝赋值运算符（deep copy）
  • 析构函数（释放资源）

提示：这就是经典的 Rule of 3。在现代 C++ 中通常还要补上移动构造/移动赋值（Rule of 5），这里先聚焦“深浅拷贝”主题。

#include <iostream>

class MyClass {
public:
    int* data;
    int  m;

    // 构造函数
    explicit MyClass(int value)
        : data(new int(value)), m(1) {}

    // 拷贝构造（深拷贝）
    MyClass(const MyClass& other)
        : data(new int(*other.data)), m(other.m) {}

    // 拷贝赋值（深拷贝）
    MyClass& operator=(const MyClass& other) {
        if (this == &other) return *this;
        delete data;                 // 释放旧资源
        data = new int(*other.data); // 复制新资源
        m = other.m;
        return *this;
    }

    // 析构函数
    ~MyClass() {
        delete data;
    }
};

int main() {
    MyClass original(42);
    MyClass copy = original; // 深拷贝

    std::cout << "Original: " << *original.data << ", m=" << original.m << "\n";
    std::cout << "Copy:     " << *copy.data << ", m=" << copy.m << "\n";

    // 修改拷贝对象
    *copy.data = 100;
    copy.m = 12;

    std::cout << "After modifying copy:\n";
    std::cout << "Original: " << *original.data << ", m=" << original.m << "\n"; // 仍为 42, 1
    std::cout << "Copy:     " << *copy.data << ", m=" << copy.m << "\n";         // 100, 12
}

5. 实战建议（简明版）

  1. 优先使用 RAII 容器，避免手写 new/delete：
    • 动态数组用 std::vector<T>
    • 单个对象所有权用 std::unique_ptr<T>
    • 共享所有权用 std::shared_ptr<T>（谨慎使用）
  2. 如果类 拥有资源（own resource），就要认真实现拷贝/移动语义：至少满足 Rule of 3；现代 C++ 通常满足 Rule of 5。
  3. 若不希望被拷贝，可以显式禁用：MyClass(const MyClass&) = delete;

6. 你这页示例中的关键点（总结）

  • data 是指针成员，默认拷贝会导致浅拷贝风险。
  • 通过自定义拷贝构造函数 MyClass(const MyClass& other) 并重新 new，可以实现深拷贝：两个对象各自拥有独立内存。
  • 修改 copy 的 *data 不会影响 original 的 *data，这是深拷贝的直接体现。
